# Google Developer Style Guidance

These topic notes capture Google developer documentation guidance that forms the cross-project writing standard. Each note lists the Google pages it covers.

Use the notes as practical guidance, and apply them with the house overrides, which win on any conflict. The repository writing rule wins over both.

## Claims and Reader Needs

- **[Avoid Excessive Claims](excessive-claims.md)**: Support performance claims and state security properties without guarantees.
- **[Write for Translation](translation.md)**: Use clear, stable terms and sentence patterns for global readers.
- **[Use Jargon Carefully](jargon.md)**: Replace, explain, or link specialized terms when readers need them.
- **[Write Timeless Documentation](timeless-documentation.md)**: Describe product behavior without wording that ages quickly.
- **[Use a Clear Tone](tone.md)**: Write with respect and directness, without filler or forced humor.

## Grammar and Sentence Mechanics

- **[Use Active Voice](voice.md)**: Name the actor when it helps readers understand responsibility.
- **[Form Possessives](possessives.md)**: Apply apostrophe rules and avoid possessive product names and identifiers.
- **[Use Prepositions Clearly](prepositions.md)**: Prefer natural word order and remove needless prepositions.
- **[Structure Sentences](sentence-structure.md)**: Put conditions and goals before actions that depend on them.
- **[Describe Reference Methods](reference-verbs.md)**: Describe each method's action in third-person present tense.

## Document Structure and Links

- **[Write Clear Headings](headings.md)**: Use task verbs, concept nouns, and semantic heading order.
- **[Use Tables Well](tables.md)**: Use tables for related data and provide accessible context.
- **[Write Clear Cross-References](cross-references.md)**: Use concise link labels and send readers to precise destinations.
