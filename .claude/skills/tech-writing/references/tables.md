# Use Tables Well

Use tables for related data and mark up headers so readers can navigate them.

Use a table when readers need to compare several related attributes. Use a list for simple items, steps, or a one dimensional set.

## Choose and Introduce Tables

- Use a table for items with three or more related details. Use a description list or table for term and definition pairs.
- Use a description list or a table for term and definition pairs. Avoid a one-row table unless consistent reference formatting needs it.
- Convert a one-column table to a list. Do not split a long one-dimensional list into columns to save space.
- Do not use a table for page layout, code samples, long one-dimensional lists, or content inside numbered procedures.
- Start each table with a complete sentence that explains its purpose. Use a colon if the table follows at once, or a period if other content comes first.
- Place the table near the related text. Do not place a table inside a sentence.
- Use a caption when several tables appear close together. Put the caption first, number it, use sentence case, and omit final punctuation.
- Refer to a table by its number in prose. Avoid direct links to the table when a numbered reference works.
- Put footnotes directly after a table when you need them.

## Make Tables Accessible

- Use `th` for header cells and `td` for data. Add `scope` where it clarifies the header relationship.
- Use sentence case for short column headings. Do not use punctuation at the end.
- Do not rely on color or styling alone to identify headers.
- Avoid merged cells. Order rows logically or alphabetically.
- Do not merge cells with `colspan` or `rowspan`.
- Split a long or complex table when smaller tables are easier to understand.
- Use separate paragraphs in a cell when it has more than one paragraph. Do not use `br` for paragraph breaks.
- Provide text alternatives for meaningful images and symbols. Do not put unique information only in an image.
- Keep table markup semantic. Align every column and match each separator row to the column width.
- Use responsive styling when the target supports it.

Source: [Google guidance on tables](https://developers.google.com/style/tables).
