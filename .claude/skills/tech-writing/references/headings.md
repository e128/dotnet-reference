# Write Clear Headings

Use headings that describe the section and follow a clear semantic hierarchy.

Use headings to show document structure, not only to change visual appearance. Match the heading form to the section content.

## Choose Heading Text

- Start procedure headings with a base form verb, such as “Create an instance.”
- Start conceptual headings with a noun phrase, such as “Cloud migration.”
- Mark steps that apply only to some readers with “Optional:” at the start.
- Use one distinct H1 for the page. Do not repeat the page title as a section heading.
- Use sentence case unless the active style guide requires another form. This repository uses title case for headings.
- Use familiar abbreviations. Explain an abbreviation in the text that follows.
- Do not number headings, add links, or place code items in a heading unless required.

## Keep Structure Semantic

- Use heading tags or Markdown levels in logical order. Do not skip a level.
- Do not leave a heading without content.
- Mix task headings and concept headings when sections need different forms.
- Avoid a gerund as the first word when a clear alternative exists. Keep established terms such as Billing when no good alternative fits.
- Refer to a set of lower-level headings as “the following sections.”

Source: [Google guidance on headings](https://developers.google.com/style/headings).
