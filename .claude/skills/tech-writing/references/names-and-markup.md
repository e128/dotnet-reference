# Names, Files, and Markup

Rules for example names, filenames, trademarks, semantic HTML, HTML formatting and Markdown.

## Example Names and Data

- Use reserved example domains: `example.com`, `example.org`, `example.net`.
- Never use a real domain, email address, person, phone number or card number. Use `user@example.com` for an email address.
- IPv4 documentation ranges: 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24. IPv6: 2001:db8::/32.
- Use fictional people with varied names. Use "Example Organization" for a company.
- Give a project a meaningful name with an appended number (`production-1`). Avoid `foo`, `bar` and `baz`.

## Filenames and Trademarks

- Name new files in lowercase ASCII with hyphens: `query-data.html`. Use no generic names such as `document1.html`.
- Match a directory that consistently uses another convention.
- Do not use a file type as a verb. Write "Extract a zip file", not "Unzip".
- Follow the trademark owner's guidelines. Use a trademark as a modifier, never as a verb, and never in a plural or possessive form.

## HTML and Markdown

- Use an element for its meaning: `em` for emphasis, `strong` for importance, `cite` for a work title. Use CSS for a purely visual effect.
- Use `br` only for a break that belongs to the content. Do not use tables or frames for layout.
- Indent with two spaces. Write element and attribute names in lowercase. Leave no trailing spaces.
- Break lines at 80 characters. Put a URL longer than that on its own line.
- Use Markdown or HTML, whichever the team or template already uses. Repo docs are Markdown.

## Link Targets

- Write anchors in lowercase with hyphens: `#introduction-to-everything`.
- Add a custom anchor to a heading that readers link to often. Do not rely on auto-generated anchors.
- Keep an old anchor when you revise a heading. If you change an anchor, update every link that points to it.
