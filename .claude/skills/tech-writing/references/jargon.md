# Use Jargon Carefully

Use specialized terms only when they help the intended reader understand or find the topic.

Jargon can hide meaning across teams, experience levels, cultures, and languages. Replace vague or specialized terms when ordinary words are clear.

## Decide Whether to Keep a Term

- Use a precise common word when it carries the same meaning.
- If search terms require jargon, explain it in plain language and include the term once.
- For a term used once, define it briefly or link to a reliable explanation.
- For a term used again, define it at first use or link to its definition.
- Keep the literal term when you refer to code or a command. Format it as code and explain its role.
- Do not use terms that exclude or offend readers. Check the active project word list.

## Examples

Write “review which processes succeeded after a project” instead of relying on an unexplained business idiom.

Write “import” or “load” instead of “ingest” when the simple verb is accurate. Explain terms such as cold standby when readers need the technical meaning.

When a command contains a legacy term, quote the exact command text as code and explain the intended action in plain language.

Source: [Google guidance on jargon](https://developers.google.com/style/jargon).
