# Word Choice and Product Names

Preferred and avoided words from the Google word list, product-name rules and filler phrases.

## Words to Replace

| Avoid | Write |
| --- | --- |
| "allows you to", "enables you to" | lets you |
| and/or | and, or or |
| i.e., e.g. | that is, for example |
| etc., and so on | name the items |
| click here | descriptive link text |
| abort | stop, exit, cancel, end |
| access (verb) | see, edit, find, use, view |
| admin | administrator, unless it is a UI label |
| whitelist, blacklist | allowlist, denylist |
| comprise | consist of, contain, include |
| disable, for a broken item | inactive, unavailable, turn off |
| may, for possibility | can or might |
| should, for a requirement | must |
| deprecate, to mean removed | remove, shut down |

## Words to Cut

- Time-anchored words in product docs: currently, now, new, newer, existing, latest, soon, eventually, presently, "as of this writing".
- Filler: "please note", "at this time", "simply", "easy", "it's that simple".
- Superlatives and guarantees: "fastest", "always works", "ensures complete protection". Use measured wording: "helps prevent".
- Jargon with a plain equivalent. Define unavoidable jargon on first use or link to a trusted definition.
- Slang, buzzwords and figurative language.

## Product and Feature Names

- Title-case a product name and match its official form. Keep official lowercase names such as macOS, and reword so they do not open a sentence.
- Do not put "the" before a product name. Put "the" before a tool or API name: "the Transcoder API".
- Do not use a product name as a verb, a plural or a possessive.
- Keep feature names lowercase unless the feature has an official capitalized name.
- Use the full name on first mention. Shorten only to match the UI.
- Use "data" as a singular noun: "The data is".
